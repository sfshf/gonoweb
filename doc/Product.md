# gono web 产品设计说明

## 核心概念

- User（用户）
- Domain（域租户/公司/机构）
- Role（角色）
- Resource（菜单/控件/API）

 User（用户）、Domain（域租户/公司/机构）和Role（角色），这三者之间的关联关系落实到表结构设计（即`t_casbin_rule`表）。

### User（用户）

应用的可预见的使用者。应用服务的初始状态会创建唯一的root用户。用户是单独的抽象概念。

同一用户在同一域租户下可被分配不同的角色。

### Domain（域租户/公司/机构）

注册到应用服务上的可预见的抽象的组织形式，如公司、工厂等。域租户也是单独的抽象概念。

### Role（角色）

注册到应用服务上的可预见的抽象的资源/权限的集合或代表，如老板、总监、管理员、船员、船长等。角色也是单独的抽象概念，比如，A、B公司均使用本应用服务，A公司有老板角色，B公司也有老板角色。

不同域租户的同名角色，其对应用服务内的资源的权限是不一定相同的。

### Resource（菜单/控件/API）

菜单、控件、API统称为资源。资源之间（菜单与控件、控件与API）均采取弱相关设计，即关联关系不落实到表结构设计（资源记录之间没有关系记录）。资源也是单独的抽象概念。

资源是应用服务内的所有可抽象的数据/信息等。

### 非常重要：基础概念数据的创生逻辑

用户、域租户、角色、资源的数据记录均是独立创建管理的。

`t_casbin_rule`表是四者关系表。

根据casbin工具的设计逻辑，

```txt
[role_definition]
g = _, _, _
```

该模型定义了角色结构；

```txt
[policy_definition]
p = sub, dom, obj, act
```

该模型定义了权限结构；

所以，分别创建用户、域租户、角色、资源的数据后，在某一域租户下给某一角色分配资源时，会在`t_casbin_rule`表创建`ptype=p`的记录；此时，只意味着创建了权限策略记录，而还没有角色记录。只有将该域租户的这一角色分配给用户时，会在`t_casbin_rule`表创建`ptype=g`的记录；此时，意味着创建了角色记录了。

这样的数据记录创生过程是符合casbin的模型定义逻辑的，且方便后期对应用权限功能的扩展。
